# حالة مشروع مواعيد

آخر تحديث: 2026-10-20.

## مصدر الكود

المستودع المعتمد: https://github.com/maon115-lgtm/salon — الفرع `main`.
يُحفظ فيه التطبيق وملفات إنشاء الجداول والاختبارات، دون مفاتيح سرية أو قواعد البيانات المحلية.

## قاعدة البيانات

- الخدمة المستهدفة: Supabase PostgreSQL.
- جاهز في الكود: الجداول، ربط الخادم، صلاحيات الوصول، الحفظ المشروط بالإصدار، واختبارات PostgreSQL المحلية.
- مشروع Supabase السحابي: لم يتم اختياره أو إنشاؤه بعد.
- تطبيق الجداول على السحابة: لم يتم.
- إعداد مفاتيح الاتصال في الخادم: لم يتم.
- التحقق من الحفظ والقراءة على السحابة: لم يتم.
- القاعدة المحلية السابقة: محفوظة، وتستمر النسخة المحلية باستخدامها حتى تهيئة Supabase.
- نقل بيانات التجربة للسحابة: لم يتم؛ يتطلب مراجعة البيانات وربط المالك الحقيقي بدل هوية الاختبار المحلية.

## ما يمنع إكمال الربط

تم تسجيل الدخول إلى Supabase. فُحصت منظمتا Salon وmaon115-lgtm's Org، وكلتاهما تعرض صفر مشاريع وقت التحقق. فُتح نموذج مشروع salon داخل منظمة Salon المجانية؛ إنشاء المشروع ما زال غير مؤكد. بعد إكمال الإنشاء، نطبق ملف SQL ونضبط أسرار الخادم ونختبر الاتصال والحفظ.

## GitHub وSupabase

رفع الكود إلى GitHub لا ينشئ قاعدة البيانات ولا يطبّق ملفات SQL تلقائيًا. تكامل Supabase مع المستودع وتطبيق التغييرات تلقائيًا لم يُفعّلا بعد.

## التحقق بعد الاتصال

من مجلد المشروع، بعد ضبط `.dev.vars`:

```text
npm run db:check:supabase
```

الفحص للقراءة فقط: يتحقق من الاتصال والمفتاح ودالة الوصول والجدول، دون طباعة بيانات العملاء أو الأسرار. تبقى تجربة الحفظ والحجز واختبار الصلاحيات على السحابة خطوة منفصلة.
